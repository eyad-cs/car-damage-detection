# بصيرة — شرح مبسط للملفات

## التشغيل

1. فك الضغط، ثم افتح مجلد `baseera-frontend`.
2. اضغط مرتين على `run_site.bat` وانتظر ظهور `Running on`.
3. افتح `http://127.0.0.1:8000` واترك نافذة التشغيل مفتوحة.

تحتاج Python مثبتًا على Windows، واتصالًا بالإنترنت لتثبيت المكتبتين أول مرة.
افتح الموقع من هذا العنوان حتى يعمل Python داخل صفحة القطع؛ فتح HTML بالنقر عليه وحده لا يشغّل البحث.

## ترتيب صفحة HTML

تقرأ الصفحة من فوق لتحت بهذا الترتيب:

1. `head`: معلومات الصفحة، ترميز العربية، عنوان التبويب، وربط CSS.
2. `body`: كل المحتوى الظاهر للمستخدم.
3. `header`: الكلاس الذي ينسّق الشعار والقائمة أعلى الموقع.
4. `main`: الكلاس الذي ينسّق المحتوى الرئيسي لكل صفحة.
5. `footer`: الكلاس الذي ينسّق أسفل الصفحة.
6. `chat`: المساعد الموجود أسفل الشاشة.

قبل كل قسم تعليق عربي قصير يشرح وظيفته، مثل `<!-- الهيدر: الشعار وروابط الصفحات -->`.
تعليقات HTML تكون بين `<!-- -->`، وتعليقات CSS بين `/* */`، وتعليقات Python تبدأ بـ `#`.
التعليق للشرح فقط، ولا يظهر في تصميم الصفحة.

## الفرق بين class و id و name

| الخاصية | معناها | مثال من المشروع |
| --- | --- | --- |
| `class` | اسم نربطه بالتنسيق، ويمكن تكراره على عدة عناصر | `class="field"` لكل مجموعة عنوان وحقل |
| `id` | اسم يميز عنصرًا واحدًا داخل الصفحة | `id="car-model"` لحقل الطراز |
| `name` | اسم المعلومة عند إرسال النموذج إلى Python | `name="model"` |
| `for` | يربط عنوان الحقل بالـ id الخاص به | `for="car-model"` |

مثال من صفحة القطع، مع اختصار خصائص الحقل للتوضيح:

```html
<!-- حقل طراز السيارة -->
<div class="field">
  <label for="car-model">الطراز</label>
  <input id="car-model" name="model" placeholder="مثل: Camry">
</div>
```

`div` يجمع العناصر، و`label` اسم الحقل، و`input` مكان الكتابة.
في CSS نكتب `.field` بالنقطة لاختيار الكلاس. لو احتجنا تنسيق عنصر بالـ id نكتب `#car-model`.
يمكن وجود `car-model` في صفحتين مختلفتين، لكن لا نكرره داخل الصفحة نفسها.
`class="box car-form"` يعني أن العنصر يستخدم تنسيقين: الصندوق العام، وصندوق بيانات السيارة.

## كيف يعمل البحث؟

1. المستخدم يملأ النموذج في `parts.html` ويضغط «ابحث وقارن».
2. سطور JavaScript في نهاية الصفحة تظهر رسالة «جاري البحث».
3. `app.py` يأخذ بيانات النموذج، ويحوّل السنة إلى رقم.
4. يرسل البيانات إلى رابط `API_URL` مع المفتاح `API_KEY`.
5. يستقبل النتائج ويضعها في `items`، ثم يفتح صفحة القطع بالنتائج.

في `app.py`: `format_price` يكتب السعر والعملة، و`is_web_link` يتحقق أن الرابط يبدأ بـ HTTP أو HTTPS، و`show_page` يعرض الصفحة ويعالج البحث.
`try` و`except` يمنعان توقف الصفحة عند خطأ اتصال أو إدخال سنة غير صحيحة.

داخل `parts.html` ستجد أوامر قوالب Flask:

| الصيغة | معناها |
| --- | --- |
| `{{ item.title }}` | وضع عنوان المنتج داخل الصفحة |
| `{% for item in items %}` | تكرار بطاقة المنتج لكل نتيجة |
| `{% if items %}` | عرض شيء بشرط وجود نتائج |
| `request.form.get(...)` | إبقاء القيم التي كتبتها داخل الحقول بعد البحث |

هذه الأوامر يعالجها Python قبل إرسال الصفحة إلى المتصفح، وهي ضرورية لعرض نتائج البحث الحالية.

## ربط خدمة صاحبك

رابط الخدمة الحالي في `API_URL` هو `https://baseerah.duckdns.org/webhook/parts-search`.
الخدمة تقبل البحث بدون مفتاح وقت الاختبار، لذلك `API_KEY = ""` افتراضيًا. إذا فعّلتم مصادقة `x-api-key` لاحقًا، ضع المفتاح الفعلي بين علامتي التنصيص ثم أعد تشغيل الموقع.
لا تكتب عبارة عربية مكان المفتاح؛ هذه القيمة تُرسل في ترويسة HTTP. غيّر `API_URL` إذا تغيّر الرابط.

أسماء البيانات المرسلة هي `vin`, `make`, `model`, `year`, `partName`, `partType`, `condition`.
لم نغيّر `name` للحقول لأن خدمة n8n تستقبل هذه الأسماء. عندما تترك VIN فارغًا نرسله فارغًا.
الخدمة ترجع JSON فيه `success` و`items`، وقد ترجع `message`.
عند كتابة مفتاح فعلي يرسل في ترويسة `x-api-key`، وعندما تكون قيمته فارغة لا نرسل هذه الترويسة. لا ترفع مفتاحك إلى GitHub عام.

## ما الذي بُسّط وما الذي بقي؟

- تغيرت اختصارات الكلاسات والـ IDs وأسماء صور الأيقونات إلى أسماء تصفها.
- حُذفت تنسيقات غير مستخدمة و3 صور غير مستخدمة وIDs لا يحتاجها الكود.
- الأسئلة والمساعد يستخدمان `details` و`summary`: عنصران من HTML لفتح المحتوى وإغلاقه بالضغط، بدون JavaScript أو مربعات اختيار مخفية.
- ملف CSS مرتب إلى أقسام مشروحة؛ `display: flex` يرتب العناصر بجانب بعض، و`@media` يغير بعض الأحجام والترتيب على الجوال.
- بقي `meta charset="UTF-8"` لأن حذف ترميز العربية قد يجعلها تظهر كرموز في بعض طرق فتح الملف. نجاحها عندك بدونه لا يضمن ذلك في كل الحالات.
- بقي `meta viewport` حتى يظهر تصميم الجوال بالحجم الصحيح.
- بقيت الخطوط والألوان والمقاسات اللازمة للمحافظة على التصميم، وترخيص الخط، والتحقق الأساسي من المدخلات والروابط.
- صححنا عرض السعر أو الشحن بقيمة صفر، ورسالة عدم وجود نتائج، ورسالة السنة غير الصحيحة.

التبسيط هنا حذف الزائد وجعل الأسماء والشرح واضحين. التعليقات والأسماء الكاملة قد تزيد حجم النص قليلًا، لذلك عدد الأسطر وحده ليس مقياسًا للتعقيد.

تحليل الصور وزر إرسال المساعد غير مربوطين في الملفات الأصلية، والتقرير ما زال مثالًا ثابتًا. بحث القطع يحتاج رابط n8n شغالًا؛ المفتاح مطلوب فقط إذا فعّلتم المصادقة.

## التحقق من النسخة

تمت مقارنة 21 لقطة بالشكل الأصلي على عروض شاشة 1440 و900 و390 بكسل، بما يشمل فتح المساعد والأسئلة وبطاقات النتائج؛ الصور متطابقة. تم اختبار إرسال حقول البحث وعرض الرد ورسائل الخطأ ببيانات تجريبية. في تحديث 9 أكتوبر اختُبر رابط n8n الحالي فعليًا بدون مفتاح، وأعاد 5 منتجات. اختُبر كذلك إرسال الطلب عبر HTTP محليًا بمفتاح وبدونه، والتعامل مع المفتاح العربي والرد غير الصحيح وأخطاء الخدمة دون إسقاط الصفحة.

## إصلاح البحث — 9 أكتوبر 2026

كان إرسال عبارة «ضع مفتاح x-api-key هنا» في ترويسة الطلب يسبب UnicodeEncodeError وصفحة Internal Server Error. أصبح المفتاح فارغًا افتراضيًا، ولا تُرسل ترويسة المصادقة إلا إذا كتبت مفتاحًا. جرى تحديث رابط Cloudflare القديم إلى الرابط الحالي، وإظهار رسائل واضحة لأخطاء HTTP وتأخر الخدمة وصيغة الرد غير الصحيحة. التصميم وملفات HTML وCSS كما هي.
